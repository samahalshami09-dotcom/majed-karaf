# دليل تصنيف ومحادثة الـ Agent AI — ربطه بالمعمارية

**المصدر:** ملف PDF من ماجد كرف بعنوان "دليل تصنيف ومحادثة الـ Agent AI" (9 صفحات، تصميم جاهز بهوية MK).
**الخلاصة:** الدليل هو عملياً **Agent 1 (Conversation AI)** + منطق المبيعات. بيتركّب فوق Agent 2 (Intake) و Agent 3 (Broker) يلي بنيناهم سابقاً.
**الخريطة البصرية (Artifact):** https://claude.ai/code/artifact/282917c1-5f90-4401-b61a-3e79b5c85ea0

---

## 1. ملخص محتوى الدليل
1. **تصنيف جهة الاتصال** — 6 تصنيفات بالـTag: `friend/family` (البوت يوقف فوراً)، `customer`، `Developer`، `agency`، `broker`، `owner`.
2. **إذا الشخص غير مصنّف** — رسالة تعريفية قصيرة + سؤال واحد: "شراء أم بيع؟".
3. **مسار الشراء** — كل الطلبات تتوجّه تلقائياً لـ**مشاريع الشركة (Project)**.
4. **منطق التسعير** — كاش = خصم 15% على السعر المعلن؛ تقسيط = بدون خصم (السعر الإجمالي + خطة المطوّر). سقف الجنسية التركية = 400,000 دولار (المجموع، مو عدد الوحدات).
5. **ترتيب العرض** — ابدأ بالمشروع الأرخص ضمن المعايير، ثم ترقَّ تدريجياً.
6. **جدول المتابعة** — يوم 0، 3، 5، 7، 14، ثم أسبوعي (أسبوع 3–4)، ثم كل 15 يوم بعد الشهر الأول.
7. **حالة إعادة البيع (Resale)** — الاستثناء الوحيد؛ يتحوّل المصدر من Project إلى **Property** (السوق الثانوي) فقط عند تصريح العميل الصريح.
8. **مسار البيع** — يجمع مواصفات العقار ويدرجه بقائمة "للبيع" داخل قاعدة Property.
9. **نص System Prompt جاهز للصق** — بآخر صفحة (الصندوق الأسود).

## 2. كيف يربط بالمعمارية
- **Agent 1 = الباب الوحيد.** كل رسالة تمرق منه؛ التصنيف (Tag) هو الراوتر.
- التوجيه حسب التصنيف:
  - `friend/family` → وقوف.
  - `customer` → مسار المبيعات (شراء/بيع)؛ عند اكتمال المعايير → **Agent 3** للبحث والترتيب.
  - `broker` / `agency` / `Developer` / `owner` → مصادر توريد → **Agent 2 (Intake)** لإدخال Project/Property.
- هذا يحلّ التباس "broker-facing vs customer-facing": Agent 1 يخدم الاثنين، والتصنيف يفرز المسار.

## 3. ⚑ أهم تعارض — قرار مطلوب
الدليل يجعل **الافتراضي = Project (مشاريع الشركة)** و Property استثناء لإعادة البيع فقط.
لكن Agent 3 و Workflow البحث (Opportunity Property Matcher) مبنيين على البحث داخل **Property**.
→ لازم تعديل مسار البحث: **Project أولاً**، والنزول لـProperty فقط بحالة الـResale.

## 4. أين تعيش قواعد التسعير
| القاعدة | المكان |
|---|---|
| كاش = خصم 15% | برومبت Agent 1 + ترتيب Agent 3 |
| تقسيط = بدون خصم | برومبت Agent 1 |
| سقف الجنسية 400,000 دولار | فلتر بحث (Agent 3 / Workflow) |
| ابدأ بالأرخص | قاعدة ترتيب (ranking) بـAgent 3 |

## 5. الحقول والـTags للربط (موجودة بحساب ماجد غالباً)
`contact.tag` (الراوتر) · `property-intake-ready` (يشغّل Agent 2) · `Budget Max` · `Budget Currency` · `property_location_interest` · `Property Type` · `Client Needs Citizenship` (يفعّل سقف 400,000) · `Client Needs Residence` · `Client Installment` · علاقة `Project 1 → Property N`.

## 6. جدول المتابعة = Workflow منفصل
تسلسل اليوم 0–3–5–7–14–أسبوعي–كل15يوم = Workflow متابعة (nurture) مستقل، ضمن التسويق التشغيلي. يتفعّل عند إرسال Agent 1 للعرض الأول.

## 7. القرارات المفتوحة قبل أي بناء
1. اعتماد Project كأساس بدل Property (توصية: نعم).
2. بناء Agent 1 كـDraft آمن من الـSystem Prompt الجاهز (توصية: نعم، بدون نشر/حذف).
3. تقسيم منطق التسعير بين Agent 1 و Agent 3.
4. توقيت بناء Workflow المتابعة (مع الأساس أو بعده).

**الحالة:** لم يُبنَ أي شيء جديد بناءً على هذا الدليل بعد — هذا مستند ربط ومرجعية فقط، بانتظار قرار Sema.
